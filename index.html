Technical Definition & Threat Mechanics

What is the WordPress Upgrade Race Condition & RCE Vulnerability?

The WordPress Upgrade Race Condition occurs during routine core, plugin, or theme updates handled by class-wp-upgrader.php. WordPress downloads the archive into the temporary directory wp-content/upgrade/ and extracts contents using unzip_file().

During physical disk extraction and prior to directory relocation, PHP files reside inside the publicly accessible DocumentRoot. If the web server lacks perimeter restriction rules and PHP-FPM executes scripts in that directory, concurrent requests can invoke uncompressed files, leading to Remote Code Execution (RCE).

  • ✖ Directory /wp-content/upgrade/ directly accessible via HTTP.

  • ✖ WP_TEMP_DIR constant unset, leaving files in public web root.
  • ✖ No edge WAF filtering rules dropping requests to transient paths.
Hardened Server (TAVARDT Zero Trust)
  • ✔ Nginx / Apache rule blocking wp-content/upgrade/ with immediate 403 Forbidden.
  • ✔ Directory indexing categorically disabled (Options -Indexes).
  • ✔ FastCGI directive strictly denying PHP script execution in content folders.
  • ✔ WP_TEMP_DIR isolated outside DocumentRoot (/var/www/tmp/) with 0750 permissions.
  • ✔ Cloudflare WAF custom rule dropping all calls to transient upgrade folders.

Frequently Asked Questions on WordPress Upgrade Security

When WordPress updates a plugin or theme, it downloads the zip package and unpacks it inside wp-content/upgrade/. During the brief time window before files are moved to their final directory, a rapid concurrent request can invoke a newly extracted PHP script if the server permits execution.

Upgrade and upload folders must never execute server-side PHP scripts. Restricting script execution prevents web shells, backdoors, and transient files from running.

Defining WP_TEMP_DIR in wp-config.php specifies an isolated folder outside the web server DocumentRoot (e.g. dirname(__DIR__) . '/tmp/'). External users cannot reach transient files via HTTP.
